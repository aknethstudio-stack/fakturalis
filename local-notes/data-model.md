# Data model — InvoiceForge (local notes)

This cheatsheet documents a pragmatic relational data model for a solo (and future multi-user)
invoicing app running on Supabase (PostgreSQL). It includes an ERD, SQL DDL, indexes, Row Level
Security (RLS), and operational notes.

Scope (MVP → later):

- Clients
- Products
- Invoices
- Invoice items
- Payments
- Optional: Organizations (future), Profiles (future)

Conventions

- Primary keys: uuid (generated by gen_random_uuid()).
- Timestamps: timestamptz with default now() at UTC.
- Money: numeric(14,2) for totals; unit prices numeric(14,4) if needed; VAT rate numeric(5,4) as a
  ratio (e.g., 0.23).
- Currency: ISO 4217 code (text(3), uppercase via CHECK).
- RLS: per-owner (simple) with path to multi-user orgs.
- All times UTC; avoid timezone conversions in DB.

## 1) ERD (ASCII)

```
auth.users (Supabase)
        │ 1
        │
        │ N
public.clients ───────────┐
(id, owner_id, ...)       │
                          │1
                          │
                          │N
public.invoices ──────────┬──────── public.invoice_items
(id, owner_id, client_id, │         (id, invoice_id, product_id?, name, qty, unit_price, vat_rate)
 number, status, dates,   │
 currency, totals ...)    │
                          │
                          └──────── public.payments
                                    (id, invoice_id, amount, method?, status, paid_at)

public.products
(id, owner_id, name, sku?, unit_price, vat_rate_default, ...)

-- Future (multi-user):
public.organizations
(id, name, ...)

public.memberships
(user_id -> auth.users.id, organization_id -> organizations.id, role)
```

Notes

- `owner_id` ties each row to the Supabase user (simple RLS).
- Unique constraints enforce per-owner uniqueness (e.g., invoice number, product SKU).
- Optional future org model replaces `owner_id` with `(organization_id, created_by)` and membership
  RLS.

## 2) SQL DDL (Supabase/Postgres)

Run in order. Adjust schema/constraints to your needs.

```sql
-- Extensions
create extension if not exists "pgcrypto";     -- for gen_random_uuid()
create extension if not exists "pg_trgm";      -- for search on name/sku LIKE/ILIKE

-- Utility: updated_at trigger
create or replace function public.set_updated_at()
returns trigger as $$
begin
  new.updated_at = now();
  return new;
end;
$$ language plpgsql;

-- Helper enum for invoice/payment states (optional; you can use text + CHECK)
do $$
begin
  if not exists (select 1 from pg_type where typname = 'invoice_status') then
    create type public.invoice_status as enum ('draft','issued','sent','paid','overdue','voided','cancelled');
  end if;
  if not exists (select 1 from pg_type where typname = 'payment_status') then
    create type public.payment_status as enum ('pending','completed','failed','refunded');
  end if;
end
$$;

-- CLIENTS
create table if not exists public.clients (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id) on delete cascade,
  name text not null,
  vat_id text,                 -- NIP / VAT ID
  email text,
  phone text,
  address_line1 text,
  address_line2 text,
  postal_code text,
  city text,
  country_code text,           -- ISO 3166-1 alpha-2 (optional)
  notes text,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint clients_name_not_blank check (btrim(name) <> '')
);

create trigger clients_set_updated_at
before update on public.clients
for each row execute function public.set_updated_at();

-- PRODUCTS
create table if not exists public.products (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id) on delete cascade,
  name text not null,
  sku text,                                  -- optional SKU
  unit text default 'pcs',                   -- pcs/hours/kg, etc.
  unit_price numeric(14,4) not null default 0,
  vat_rate_default numeric(5,4) not null default 0,  -- e.g., 0.23 for 23%
  currency text not null default 'PLN',      -- ISO 4217

  active boolean not null default true,
  notes text,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint products_name_not_blank check (btrim(name) <> ''),
  constraint products_vat_rate_valid check (vat_rate_default >= 0 and vat_rate_default <= 1),
  constraint products_currency_len check (char_length(currency) = 3)
);

create trigger products_set_updated_at
before update on public.products
for each row execute function public.set_updated_at();

-- INVOICES
create table if not exists public.invoices (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id) on delete cascade,

  client_id uuid not null references public.clients(id) on delete restrict,
  number text not null,                            -- e.g., INV/2025/0001 (unique per owner)
  status public.invoice_status not null default 'draft',

  issue_date date not null default (now() at time zone 'utc')::date,
  due_date date not null,
  currency text not null default 'PLN',

  -- Totals (denormalized for quick queries; maintain via app or triggers)
  subtotal_net numeric(14,2) not null default 0,
  total_vat numeric(14,2) not null default 0,
  total_gross numeric(14,2) not null default 0,

  notes text,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint invoices_number_not_blank check (btrim(number) <> ''),
  constraint invoices_currency_len check (char_length(currency) = 3),
  constraint invoices_dates check (due_date >= issue_date)
);

create unique index if not exists invoices_owner_number_ux on public.invoices(owner_id, number);

create trigger invoices_set_updated_at
before update on public.invoices
for each row execute function public.set_updated_at();

-- INVOICE ITEMS
create table if not exists public.invoice_items (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id) on delete cascade,

  invoice_id uuid not null references public.invoices(id) on delete cascade,
  product_id uuid references public.products(id) on delete set null,

  name text not null,                             -- snapshot name
  quantity numeric(14,4) not null default 1,
  unit text default 'pcs',
  unit_price numeric(14,4) not null default 0,    -- net price per unit
  vat_rate numeric(5,4) not null default 0,       -- ratio e.g. 0.23

  line_net numeric(14,2) not null default 0,      -- quantity * unit_price
  line_vat numeric(14,2) not null default 0,      -- line_net * vat_rate
  line_gross numeric(14,2) not null default 0,    -- line_net + line_vat

  position int not null default 0,                -- ordering

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint invoice_items_name_not_blank check (btrim(name) <> ''),
  constraint invoice_items_qty_positive check (quantity > 0),
  constraint invoice_items_vat_rate_valid check (vat_rate >= 0 and vat_rate <= 1)
);

create index if not exists invoice_items_invoice_idx on public.invoice_items(invoice_id);
create index if not exists invoice_items_position_idx on public.invoice_items(invoice_id, position asc);

create trigger invoice_items_set_updated_at
before update on public.invoice_items
for each row execute function public.set_updated_at();

-- PAYMENTS
create table if not exists public.payments (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references auth.users(id) on delete cascade,

  invoice_id uuid not null references public.invoices(id) on delete cascade,
  amount numeric(14,2) not null,
  currency text not null default 'PLN',
  method text,                                    -- e.g., "transfer", "card", "cash"
  status public.payment_status not null default 'pending',
  paid_at timestamptz,

  notes text,

  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),

  constraint payments_amount_positive check (amount > 0),
  constraint payments_currency_len check (char_length(currency) = 3)
);

create index if not exists payments_invoice_idx on public.payments(invoice_id);
create index if not exists payments_paid_at_idx on public.payments(paid_at);

create trigger payments_set_updated_at
before update on public.payments
for each row execute function public.set_updated_at();

-- UNIQUE CONSTRAINTS / INDEXES (search & integrity)
create unique index if not exists products_owner_sku_ux on public.products(owner_id, sku) where sku is not null;

create index if not exists clients_owner_name_trgm_idx on public.clients using gin (name gin_trgm_ops);
create index if not exists products_owner_name_trgm_idx on public.products using gin (name gin_trgm_ops);
create index if not exists invoices_owner_issue_date_idx on public.invoices(owner_id, issue_date);
create index if not exists invoices_owner_status_idx on public.invoices(owner_id, status);

-- Optional: Materialized view / regular view for invoice totals (if not denormalizing)
-- Here we keep denormalized totals in invoices; but you can recompute like:
```

## 3) Row Level Security (RLS)

Simple per-owner RLS (solo user model). All policies follow the rule: a row is accessible only if
`owner_id = auth.uid()`.

```sql
-- Enable RLS
alter table public.clients enable row level security;
alter table public.products enable row level security;
alter table public.invoices enable row level security;
alter table public.invoice_items enable row level security;
alter table public.payments enable row level security;

-- Policies (SELECT / INSERT / UPDATE / DELETE)
-- CLIENTS
create policy clients_select on public.clients
  for select using (owner_id = auth.uid());

create policy clients_insert on public.clients
  for insert with check (owner_id = auth.uid());

create policy clients_update on public.clients
  for update using (owner_id = auth.uid()) with check (owner_id = auth.uid());

create policy clients_delete on public.clients
  for delete using (owner_id = auth.uid());

-- PRODUCTS
create policy products_select on public.products
  for select using (owner_id = auth.uid());

create policy products_insert on public.products
  for insert with check (owner_id = auth.uid());

create policy products_update on public.products
  for update using (owner_id = auth.uid()) with check (owner_id = auth.uid());

create policy products_delete on public.products
  for delete using (owner_id = auth.uid());

-- INVOICES
create policy invoices_select on public.invoices
  for select using (owner_id = auth.uid());

create policy invoices_insert on public.invoices
  for insert with check (owner_id = auth.uid());

create policy invoices_update on public.invoices
  for update using (owner_id = auth.uid()) with check (owner_id = auth.uid());

create policy invoices_delete on public.invoices
  for delete using (owner_id = auth.uid());

-- INVOICE ITEMS
create policy invoice_items_select on public.invoice_items
  for select using (owner_id = auth.uid());

create policy invoice_items_insert on public.invoice_items
  for insert with check (owner_id = auth.uid());

create policy invoice_items_update on public.invoice_items
  for update using (owner_id = auth.uid()) with check (owner_id = auth.uid());

create policy invoice_items_delete on public.invoice_items
  for delete using (owner_id = auth.uid());

-- PAYMENTS
create policy payments_select on public.payments
  for select using (owner_id = auth.uid());

create policy payments_insert on public.payments
  for insert with check (owner_id = auth.uid());

create policy payments_update on public.payments
  for update using (owner_id = auth.uid()) with check (owner_id = auth.uid());

create policy payments_delete on public.payments
  for delete using (owner_id = auth.uid());
```

Optionally set column defaults for convenience (Supabase allows `default auth.uid()`):

```sql
alter table public.clients alter column owner_id set default auth.uid();
alter table public.products alter column owner_id set default auth.uid();
alter table public.invoices alter column owner_id set default auth.uid();
alter table public.invoice_items alter column owner_id set default auth.uid();
alter table public.payments alter column owner_id set default auth.uid();
```

Future (organizations):

- Replace `owner_id` with `(organization_id, created_by)`.
- Policies join `memberships` to check membership and role:
  - `exists (select 1 from memberships m where m.organization_id = table.organization_id and m.user_id = auth.uid())`.

## 4) Business rules & integrity checks

- Invoice numbering: enforce per-owner uniqueness; optional CHECK for format:
  ```sql
  alter table public.invoices
    add constraint invoices_number_format_chk
    check (number ~ '^[A-Za-z0-9_/\-\.]+$');
  ```
- Totals consistency: compute in app or via trigger/view; validate totals ≥ 0.
- Payment constraints: invoice currency = payment currency (optional):
  ```sql
  alter table public.payments
    add constraint payments_currency_matches_invoice
    check (
      currency = (select i.currency from public.invoices i where i.id = invoice_id)
    );
  ```
- VAT bounds: 0 ≤ vat_rate ≤ 1; quantities > 0; prices ≥ 0.

## 5) Sample queries

Totals per period:

```sql
select
  date_trunc('month', issue_date) as month,
  sum(subtotal_net) as net,
  sum(total_vat) as vat,
  sum(total_gross) as gross
from public.invoices
where owner_id = auth.uid()
  and issue_date between $1 and $2
group by 1
order by 1;
```

Overdue invoices:

```sql
select *
from public.invoices
where owner_id = auth.uid()
  and status in ('issued','sent')
  and due_date < (now() at time zone 'utc')::date;
```

Search clients/products (ILIKE with trigram indexes):

```sql
select id, name
from public.clients
where owner_id = auth.uid()
  and name ilike '%' || $1 || '%'
order by similarity(name, $1) desc
limit 20;
```

## 6) Performance & indexes

Recommended indexes

- FKs: invoice_items(invoice_id), payments(invoice_id).
- Temporal: invoices(owner_id, issue_date), payments(paid_at).
- Status: invoices(owner_id, status), payments(status).
- Text search: trigram GIN on clients.name, products.name, products.sku.

When to add more

- Large datasets: composite indexes for frequent filters (e.g., (owner_id, client_id, issue_date)).
- Pagination: use keyset pagination (where id > last_seen_id) for big tables.

## 7) Migrations & safety

- Wrap DDL in transactions; deploy during low-traffic windows.
- For enum changes, use `alter type ... add value` (non-transactional in vanilla PG; Supabase
  supports it carefully).
- Backfill totals if switching between denormalized and view-based totals.
- Always test RLS with anon/user/service roles.

## 8) Open extensions (future)

- Credit notes / corrections: model as invoices referencing a base invoice with negative lines or a
  distinct `kind` column.
- Partial payments: multiple payments per invoice; derive paid/unpaid status by comparing
  sum(payments) with total_gross.
- Exchange rates: store `exchange_rate numeric(14,6)` on invoices for non-PLN currencies; compute
  totals in invoice currency.
- Attachments: link table with storage (Supabase Storage) references.

## 9) Quick DML examples

Insert a client:

```sql
insert into public.clients (name, vat_id, email, city, country_code)
values ('ACME Sp. z o.o.', 'PL1234567890', 'office@acme.pl', 'Warszawa', 'PL')
returning *;
```

Create invoice + items (simplified):

```sql
-- 1) invoice
insert into public.invoices (client_id, number, issue_date, due_date, currency, status)
values ($client_id, 'INV/2025/0001', '2025-01-12', '2025-01-26', 'PLN', 'issued')
returning id;

-- 2) items (calculate line_* in app or DB)
insert into public.invoice_items (invoice_id, name, quantity, unit_price, vat_rate, line_net, line_vat, line_gross, position)
values
  ($invoice_id, 'Usługa A', 2, 100.00, 0.23, 200.00, 46.00, 246.00, 1),
  ($invoice_id, 'Usługa B', 1,  50.00, 0.08,  50.00,  4.00,  54.00, 2);

-- 3) update invoice totals (in app or via SQL)
update public.invoices i
set subtotal_net = x.net,
    total_vat   = x.vat,
    total_gross = x.gross
from (
  select
    sum(line_net) as net,
    sum(line_vat) as vat,
    sum(line_gross) as gross
  from public.invoice_items
  where invoice_id = $invoice_id
) x
where i.id = $invoice_id;
```

Record payment:

```sql
insert into public.payments (invoice_id, amount, currency, method, status, paid_at)
values ($invoice_id, 246.00, 'PLN', 'transfer', 'completed', now())
returning *;
```

## 10) Testing RLS

- As anon (no auth.uid()): expect zero rows.
- As authenticated user (owner): full access to own rows.
- As service role: bypass RLS (use carefully only on server).

Examples (SQL—replace with your client SDK usage):

```sql
-- Without auth (anon)
set role anon;
select count(*) from public.invoices; -- expect 0

-- As a user (simulate by setting a JWT in client; in SQL you can’t spoof auth.uid() directly)
-- Use Supabase client to test real requests.

-- Service role (bypass RLS) — use only in secure server context
set role service_role;
select count(*) from public.invoices; -- returns all
reset role;
```

## 11) Implementation notes

- Keep all money in numeric; avoid float.
- Store VAT as ratio (0.23) to simplify line computations.
- Denormalize totals on invoices for fast lists; recompute on write.
- If you expect many invoices, avoid regex-heavy number checks in hot paths—validate in app.
- For future organizations, plan migrations to add `organizations` + `memberships`, swap RLS to
  membership-based policies.
